# Security Policy: Clearmail Gateway

## Supported Versions

We are committed to providing security updates for the current major version. Because this gateway handles sensitive mailbox credentials, we recommend always running the latest stable release.

| Version | Supported          |
| ------- | ------------------ |
| 1.1.x   | :white_check_mark: |
| < 1.1.0 | :x:                |

## Security Model & Invariants

To maintain the integrity of the gateway on your local system, the following security invariants are enforced by design:

- **Credential Isolation:** Mailbox credentials (IMAP/SMTP) must never be stored in the repository or passed to automation agents.
- **Human-in-the-Loop (HITL):** No email can be sent via the SMTP worker without a valid, time-bound approval token generated by the user.
- **Local-Only Execution:** The Gateway API is intended to run on `localhost` or a trusted private network. Exposing it to the public internet is strongly discouraged.

## Reporting a Vulnerability

**Do not report security vulnerabilities through public GitHub issues.**

If you discover a potential security flaw, please report it via the following secure channel:

> **Contact:** ingo.giebel@gmail.com
> **Encryption:** Please use PGP encryption for the report if possible.

### Our Response Process

1.  **Acknowledgement:** We will acknowledge your report within 72 hours.
2.  **Evaluation:** We will perform a technical analysis to confirm the impact and reach.
3.  **Fix:** A patch will be developed and tested in the `dev/` branch.
4.  **Disclosure:** After the patch is released, we will provide a brief summary of the fix in the `CHANGELOG.md`.

## Responsible Disclosure

We appreciate the efforts of the security community. Please provide us with a reasonable amount of time to fix the issue before making any information public. This helps protect users of this gateway and their connected mailbox credentials.
